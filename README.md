# 试种种子的受限发放与田间材料回收

本仓库保存该业务的合成登记资料、原始变更资料及种子承运交接台的本地协议服务，并提供试种材料管理 HTTP 服务。所有机构、人员、金额和文书均为虚构，不连接真实业务系统。材料管理服务只组织演练业务与材料责任，不计算育种结论，不判断真实检疫合格。

## 运行环境

使用 Node.js 22.23.4。没有第三方 npm 依赖，package-lock.json 锁定当前依赖清单。

```bash
npm ci --ignore-scripts
npm run build
npm test
npm run start          # 试种材料管理服务，默认端口 4318
npm run start:partner  # 承运合作方服务，默认端口 4317
npm run demo           # 中文端到端演练：换址、受潮、终止回收
```

材料管理服务默认监听 4318 端口，GET /health 可查询存活状态。PORT 可更换端口，SEED_STATE 可指定持久状态文件，默认 .local/seed-trial.json。首次使用先 POST /bootstrap 建立初始用户，之后所有业务请求带 X-User-Id 请求头。接口与规则见 docs/service.md。

## 材料管理服务覆盖的责任规则

- 许可按 站点+品种+试验季+用途 精确匹配；科研放行不能用于商业推广；站点搬迁或方案换品种必须重新核准，旧许可不能沿用。
- 发种申请人不能批准自己的申请；重复申请拒绝；两个站点竞争同一批库存时，已承诺种子不能重复分配。
- 批次身份更正时，未发部分暂停核实，已播种保持真实记录并标记受影响范围，承诺逐点重新核准。
- 运输封签、交付数量、站点实际验收分别确认；未验收或验收隔离数量不能填成已播种；回执中断不会把同一包重新标成可发；发错点转送须确认目的点许可与原封样关系，不能单改地址掩盖流向。
- 部分受潮只隔离受影响数量，余下合格部分不自动报废，使用仍需有权人员对适用部分明确放行。
- 站点登记播种、留样、损耗、退回合计不超过真实接收可用量；克与粒各有计量口径，只有该批有核准换算依据时才可换算。
- 方案终止不抹去已播种事实；未用种子须完成回收或经核准销毁才能结清；回收包到库但身份未核实不并入可用库存。
- 采收材料关联原播种批次并继承用途限制，换包装不改变限制，不能对外违规发放。
- GET /plans/{id}/materials 与 GET /lots/{id}/trace 按试验和批次逐条查清未结材料与决定，GET /materials/open 列全库未结责任，不用统计汇总代替材料责任。

## 合作方服务

合作方默认监听 4317 端口，GET /health 可查询存活状态。PORT 可更换端口，PARTNER_STATE 可指定持久状态文件，默认 .local/partner.json。停止进程后用同一状态文件启动会保留合作方流水。

也可以使用 Docker 启动合作方：

```bash
docker build -t seed-trial:local .
docker run --rm -p 4317:4317 seed-trial:local
```

容器要保留状态时，将可写目录挂载到 /app/.local；该目录需允许容器 node 用户写入。测试使用临时目录与随机本地端口，可独立运行。npm test 验证资料关系、合作方协议和材料管理服务规则。

## 资料

fixtures/records.json 是业务原始资料，sourceChanges 保存后续收到的变更或申请，均没有自动导入成已批准决定。fixtures/relations.json 声明登记资料的关联字段，docs/data.md 解释计量和身份语义。fixtures/partner.json 定义合作方接口名称及字段。support/peer.mjs 提供合作方行为，docs/partner.md 是实际协议；src/ 是试种材料管理服务，docs/service.md 是其接口与规则说明，support/demo.mjs 是中文演练脚本；tests 检查协议、资料关系与材料责任规则。
